# Artwork for Atlas guides

Atlas's visual-foundation extension uses a shared illustrated shell. Where the target instance supports it, choose a built-in subject and accent per feature using optional `presentation: { illustration, accent }`: `calendar | document | compass | parcel | people`, and `sky | sage | peach`. The field changes the reusable visual vocabulary, not the product's rules. Pick the subject from the activity's real object or task; use the scene default if no option fits. An older contract-version-1 instance may reject `presentation`; see [api.md](api.md) before including it. Supporting project-specific images are separate registered `assetIds`, never the primary hero or a substitute for a rule, label, or control.

When a specific supporting image would clarify a real activity, prepare original art with an available image tool or authored raster workflow. An image-generation provider is optional. A useful recipe is a single approachable subject on a simple transparent or light background, soft sky/sage/peach accents, rounded shapes, clean silhouette, restrained texture, and enough empty space to sit beside HTML text. Keep it original: do not copy a source screenshot or reference image. Do not bake titles, instructions, product rules, numeric thresholds, arrows that assert a relationship, or interactive-looking controls into the pixels. They belong in Atlas data and accessible HTML.

Inspect the actual image before registration for subject accuracy, unwanted text, unintended claims, legibility at small sizes, and visual fit. Save its private source/generation notes and precise provenance (creator/tool, source brief or prompt, date/version where known). Export PNG, JPEG, or WebP at no more than 1 MiB. Register via the local Atlas API with a fresh asset ID, correct media type, provenance, and current revision; then reference the returned registered ID in a scoped full-feature upsert. Reuse an existing asset only when its subject and provenance still match. For a replacement, register a new ID and update references; history retains older asset references.

Verify the image endpoint and the browser view after saving. If an image fails, keep the text and supported scene usable, record the failure, and resolve the asset before reporting visual completion. Artwork adds explanation but never supplies source evidence.
